## ⚙️ Configs Controller

### `GET /configs/load`

Загружает конфиг по имени. Имя не должно содержать слова `admin`, `moderator`, `default`.

**Авторизация:** 🔐 Admin (Cookie `Token`)

**Query-параметры / тело запроса:**

| Поле | Тип | Правила |
|------|-----|---------|
| `name` | `string` | Обязательно, длина 1–32 символа |

**Response:**

```json
{
  "id": 1,
  "name": "name",
  "json": "{...}"
}
```

**Ошибки:**

| Причина | Описание |
|---------|----------|
| `!200` | Имя содержит запрещённые слова (`admin`, `moderator`, `default`) |
| `!200` | Конфиг с таким именем не найден |

---

### `GET /configs/default`

Загружает дефолтный конфиг (`default_{name}`). Только для администраторов.

**Авторизация:** 🔐 Admin (Cookie `Token`)

**Query-параметры / тело запроса:**

| Поле | Тип | Правила |
|------|-----|---------|
| `name` | `string` | Обязательно, длина 1–32 символа |

> Например, при `name = site` вернёт запись `default_site` из БД.

**Response:**

```json
{
  "id": 2,
  "name": "default_site",
  "json": "{...}"
}
```

**Ошибки:**

| Причина | Описание |
|---------|----------|
| `!200` | Нет прав / истёкшая сессия |
| `!200` | Дефолтный конфиг не найден |

### `POST /configs/save`

Перезаписывает JSON конфига по имени. Имя не должно содержать запрещённые слова.

**Авторизация:** 🔐 Admin (Cookie `Token`)

**Request body:**

```json
{
  "name": "site",
  "json": "{\"key\": \"value\"}"
}
```

**Модель `ConfigSaveModel`:**

| Поле | Тип | Правила |
|------|-----|---------|
| `name` | `string` | Обязательно, длина 1–32 символа |
| `json` | `string` | Обязательно, должен быть валидным JSON |

**Response:**

```
Status: 200 OK
Body: ""
```

**Ошибки:**

| Причина | Описание |
|---------|----------|
| `!200` | Нет прав / истёкшая сессия |
| `400` | Поля не прошли валидацию |
| `!200` | Имя содержит запрещённые слова |
| `!200` | Ошибка обновления в БД |

### `POST /users/login`

Авторизует пользователя и сохраняет токен в сессию.

**Авторизация:** не требуется

**⚠️ Cookie:** клиент должен иметь Cookie `Token` — он будет привязан к сессии в БД.

**Request body:**

```json
{
  "username": "anatoly",
  "password": "secret"
}
```

**Модель `LoginModel`:**

| Поле | Тип | Правила |
|------|-----|---------|
| `username` | `string` | Обязательно, длина 1–128 символов |
| `password` | `string` | Обязательно, длина 1–128 символов |

> Пароль передаётся в открытом виде — хэширование (SHA-256) происходит на сервере.

**Response:**

```
Status: 200 OK
Body: "success"
```

**Ошибки:**

| Причина | Описание |
|---------|----------|
| `400` | Поля не прошли валидацию |
| `!200` | Неверный логин или пароль |

## 🔐 Авторизация и роли

### Роли пользователей

| Роль | Значение | Описание |
|------|----------|----------|
| `member` | `0` | Обычный пользователь |
| `admin` | `1` | Администратор, доступ ко всем эндпоинтам |

> Роль `admin` включает в себя все права `member`.

### Схема сессий

1. Клиент генерирует токен и сохраняет его в Cookie `Token`
2. При логине (`POST /users/login`) токен привязывается к сессии в таблице `session`
3. Защищённые эндпоинты проверяют сессию через `UserSessionMiddleware`:
    - Ищут сессию по токену
    - Проверяют, что сессия не просрочена (`expired_at`)
    - Проверяют роль пользователя
    - Кладут `SessionDatabaseModel` и `UsersDatabaseModel` в `FeatureCollection` запроса

**Срок жизни сессии:** 10 дней с момента создания.

## 🚀 Инициализация при запуске

`DatabaseInitializeService` запускается автоматически через 5 секунд после старта сервера:

**1. Создание администратора** — если пользователя с `ADMIN_USERNAME` нет в таблице `users`:
- Логин из переменной окружения `ADMIN_USERNAME`
- Пароль из `ADMIN_PASSWORD` (хранится как SHA-256)

**2. Создание конфигов** — для каждого из `site` и `settings`:
- Читает файл `public/default.{name}.json`
- Создаёт запись `default_{name}` (эталонный дефолт, не меняется)
- Создаёт запись `{name}` (рабочий конфиг)
